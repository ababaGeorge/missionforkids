# 工作交付與收尾

2026-10-04 使用者已確認跨專案共同要求，並要求落到各專案；[共同來源](https://github.com/ababaGeorge/dev-control-center/blob/main/docs/alfred/WORK_CLOSEOUT.md)。其他帳號不能讀取共同來源時，以下本地條文仍可獨立使用。

- 一般已交辦開發包含必要客觀驗證、提交本次成果、推送至已確認的私人保存目的地；本公開 repo 的推送另須符合既有公開範圍、需要審查時建立 PR，以及讀回遠端核對受驗版本。明示只分析／只本機／不推送的任務按原終點完成；不能事後把一般開發縮成只本機。正常存檔不逐次重問。
- 還能修正、驗證、審查或存檔就持續推進，不以「僅本機、未推送、未驗收」作為一般工程結案。沒有遠端先核對目的地，確實缺少才準備具體一次性確認；不猜 repo，也不把找來源交給使用者。
- 局部候選交棒要有保存連結、受驗版本、剩餘問題與接收責任。原專案主控收回相依成果並完成已授權整合，Alfred 負責查證與回收，不代寫產品。對話封存或訊息送出不等於收回或產品完成。
- 客觀工程驗證由 Agent 完成；只把必要產品選擇、本人實際體驗／裝置操作或新增授權交回使用者，先準備精確版本與可操作材料。
- 正常存檔與指定 Target 整合、正式發布、真人驗收分開核對。各專案已有合併／發布授權按原條件執行；不新增重複批准，也不因此擴大未授權正式資料、付費、安全設定或對外發訊。
- 保存前核對差異與敏感資料，僅提交本次已驗成果，保護其他代理的未提交修改與共享分支。失敗、舊 SHA 成功、skipped、本機與 hosted 通過不得混用。測試依專案當前決定，不因存檔一律跑完整雲端測試。
- 接續先查當前 Git／PR／原工單和交接：已完成卻未存檔的成果由原責任者驗證、保存並讀回；仍在修改或相依受阻的工作保持適當未完成狀態，寫明真正卡點、原責任者與下一步。既有暫緩與產品禁區不因本次入口更新恢復。
